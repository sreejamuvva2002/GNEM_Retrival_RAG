# Certification Status Checker (local LLM + browser-harness)

Checks the certification status (ISO 9001:2015, IATF 16949:2016, or any cert you choose)
of every company in the GNEM company sheet and writes **one page per company** covering
all certifications, using:

- **[browser-use/browser-harness](https://github.com/browser-use/browser-harness)**
  (vendored in [`browser-harness/`](browser-harness/), MIT license) to drive your real
  Chrome browser over CDP and fetch search-result pages, and
- a **local LLM** (Ollama / LM Studio / llama.cpp / vLLM — any OpenAI-compatible server)
  to read the search evidence and emit a strict JSON verdict per company per certification.

No cloud API keys, no data leaves your machine (searches go to DuckDuckGo).


## Quick start

```bash
cd certification_status
./setup.sh                 # installs deps + browser-harness, pulls qwen3:14b, builds companies.csv

# smoke test (3 companies, plain-HTTP search — works headless):
python3 scripts/check_certifications.py --limit 3 --backend http

# full run through your real Chrome via browser-harness:
python3 scripts/check_certifications.py --backend browser
```

Each company gets a page in `outputs/companies/<company>.md`:

```
company: ADVICS Manufacturing Georgia LLC
facility: LaGrange, Troup County
address: 1621 Lukken Industrial Dr W, LaGrange, GA 30240

ISO 9001:2015:
  org_status: confirmed_active
  facility_status: confirmed_facility
  final_label: confirmed_active_facility / active_expiry_unknown
  certification_body: DQS
  reference_no: 10000091
  scope: The Design and Manufacture of automotive disc brake pads.
  expiry_date: not visible in sources checked
  ...

IATF 16949:2016:
  ...
```

- `org_status`: `confirmed_active` | `likely_active` | `confirmed_inactive` | `not_found`
- `facility_status`: `confirmed_facility` | `different_facility` | `unknown_facility`
- `final_label` is derived from the two plus the expiry date.
- `certification_body`, `reference_no`, `scope`, `expiry_date` are copied verbatim from the
  evidence when visible (the pipeline opens the top result pages — registrar/registry sites
  are prioritized — so certificate details can actually be extracted, not just snippets).

A flat summary lands in `outputs/certification_status.csv`, and every verdict's raw
evidence text is kept in `outputs/evidence_log.jsonl` for auditing.
Re-running **resumes** where it left off; use `--fresh` to start over.

### Useful flags

| Flag | Meaning |
|---|---|
| `--cert "ISO 14001"` | check a different certification (repeatable) |
| `--backend auto\|browser\|http` | browsing backend (default `auto`: browser, else HTTP) |
| `--model qwen3:8b` | override the local model |
| `--limit N` | only first N companies |
| `--delay 3` | seconds between web requests (default 2 — be polite) |
| `--fetch-pages N` | top result pages to open per query (default 2; 0 = snippets only) |
| `--use-location` | include the sheet's location in queries — **off by default because sheet locations may be wrong**; locations are only ever passed to the LLM as unverified hints |

## Which local model is best?

The task is **reading search results and emitting strict JSON** — no vision, no long
context. What matters is instruction-following and JSON reliability.

| Model (Ollama tag) | VRAM (Q4) | Verdict |
|---|---|---|
| **`qwen3:14b`** ⭐ recommended | ~10–12 GB | Best quality/size balance; excellent JSON discipline and entity disambiguation (important when company names collide) |
| `qwen3:32b` | ~20–24 GB | Best accuracy if you have a 24 GB+ GPU |
| `qwen3:8b` | ~6–8 GB | Good on 8 GB GPUs / Apple Silicon 16 GB |
| `llama3.1:8b` | ~6–8 GB | Solid fallback; slightly weaker JSON adherence than Qwen3 |
| `mistral-nemo:12b` | ~8–10 GB | Fine alternative in the mid range |

Start with **`qwen3:14b`**; drop to `qwen3:8b` if it's slow on your hardware.
(The client already strips Qwen3's `<think>…</think>` blocks before JSON parsing.)

## browser-harness notes

- `--backend browser` attaches to your running Chrome via remote debugging. If it can't
  connect, run `browser-harness --doctor` — it walks you through enabling
  `chrome://inspect/#remote-debugging`.
- `--backend http` needs no browser at all (DuckDuckGo HTML endpoint) and is the right
  choice for servers/CI, but large runs may hit rate limits — raise `--delay`.
- browser-harness is also designed to be driven directly by a coding agent (Claude Code
  etc.); see `browser-harness/SKILL.md`. This pipeline instead calls its Python helpers
  programmatically so a small local model only has to do classification, not tool-calling —
  much more reliable with 8–14B models.

## Caveats

- Search snippets are evidence, not certificates. Treat `certified` rows with a low
  `confidence` as leads to verify against official registries (e.g. IATF's OEM databases,
  registrar certificate lookups).
- ~1,000 companies × 2 certs × ~2 s delay + LLM time ≈ several hours for a full run.
  Use `--limit` for testing and let the resume feature do the rest in batches.
