# GNEM Retrieval RAG

Runtime and indexing pipeline for answering Georgia EV supply-chain questions from
the GNEM knowledge base using PostgreSQL, pgvector, BM25, cross-encoder reranking,
and local Ollama generation.

The current architecture uses PostgreSQL + pgvector. It does not use Qdrant.

## What This Project Does

```text
Excel KB
→ normalize workbook
→ build one parent chunk per KB row
→ build five child chunks per parent row
→ store parent chunks in PostgreSQL
→ embed child chunks and store vectors in PostgreSQL/pgvector
→ retrieve child chunks with BM25 + dense pgvector
→ deduplicate child chunks by chunk_id
→ deduplicate parent IDs by parent_record_id
→ fetch full parent_chunk_text
→ rerank parent contexts with a cross-encoder
→ send only reranked top-k parent_chunk_text to the LLM
→ write answer/evaluation workbooks
```

## Repository Layout

```text
kb/
  GNEM - Auto Landscape Lat Long Updated.xlsx
  Human validated 50 questions.xlsx
  Rewritten_50_questions.xlsx

georgia_ev_intelligence/
  shared/
    config/settings.py        # .env-backed settings and paths
    data/loader.py            # KB Excel normalization
    embeddings.py             # SentenceTransformer loading and prefixes

  offline_pipeline/
    index_pgvector.py         # parent/child chunk build + PostgreSQL indexing
    postgres_store.py         # parent_chunks table
    pgvector_store.py         # child_chunks table and vector index
    chunking/                 # parent and child chunk builders

  runtime_pipeline/
    retrieval/                # BM25, dense pgvector, parent fetch
    generation/               # Ollama LLM client
    hybrid_retrieval/         # active hybrid retrieval + batch runners

  outputs/
    Normalized_kb.xlsx        # generated by normalization
    parent_chunks.xlsx        # generated by indexing command
    child_chunks.xlsx         # generated by indexing command
```

## 1. Create Environment

From the repository root:

```bash
python -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

If you use Conda instead, activate your Conda environment and then run:

```bash
pip install -r requirements.txt
```

## 2. Configure `.env`

Create `.env` in the repository root. The app loads it automatically.

Required variables used by the current code:

```bash
NEON_DATABASE_URL="postgresql://USER:PASSWORD@HOST/DB?sslmode=require"

OLLAMA_BASE_URL="http://localhost:11434"
OLLAMA_LLM_MODEL="qwen2.5:14b"
OLLAMA_TEMPERATURE="0.1"
OLLAMA_TOP_P="0.9"
OLLAMA_NUM_PREDICT="4096"

EMBEDDING_MODEL="nomic-ai/nomic-embed-text-v1.5"
EMBEDDING_LOCAL_FILES_ONLY="false"
EMBEDDING_TRUST_REMOTE_CODE="true"
EMBEDDING_DOCUMENT_PREFIX="search_document:"
EMBEDDING_QUERY_PREFIX="search_query:"

PGVECTOR_BATCH_SIZE="64"

HYBRID_RETRIEVER_TOP_K="250"
HYBRID_RERANKER_TOP_K="45"
HYBRID_RERANKER_MODEL="cross-encoder/ms-marco-MiniLM-L12-v2"
```

Notes:

- `NEON_DATABASE_URL` must point to a PostgreSQL database where extensions can be
  created.
- The indexing command creates `CREATE EXTENSION IF NOT EXISTS vector;`.
- `OLLAMA_LLM_MODEL` should be `qwen2.5:14b` for the current answer-generation
  workflow.

## 3. Start Ollama

In a separate terminal:

```bash
ollama serve
```

Pull the configured answer-generation model if needed:

```bash
ollama pull qwen2.5:14b
```

The checked-in runbook assumes `OLLAMA_LLM_MODEL=qwen2.5:14b`.

## 5. Preview Parent/Child Chunking

Use dry-run first. It builds chunks and exports debug workbooks, but does not
write to PostgreSQL.

```bash

```

Expected generated files:

```text
georgia_ev_intelligence/outputs/parent_chunks.xlsx
georgia_ev_intelligence/outputs/child_chunks.xlsx
```

Expected shape with the current KB:

```text
205 parent chunks
1025 child chunks
```

## 6. Index Into PostgreSQL + pgvector

Run this after dry-run looks correct:

```bash
python -m georgia_ev_intelligence.offline_pipeline.index_pgvector
```

This creates or updates:

```text
parent_chunks
child_chunks
```

Use this only if the embedding dimension changed or you intentionally want to
recreate the child vector table:

```bash
python -m georgia_ev_intelligence.offline_pipeline.index_pgvector --recreate-child-table
```
