  6. BM25 Retrieval — Implementation Plan

  Problem: Child chunks don't store embedding_text in PostgreSQL. The metadata
  JSONB has the field values, but not the formatted text.

  Solution options:

  A. Reconstruct text from metadata JSONB — query all child chunks' chunk_id,
  parent_record_id, chunk_type, metadata from PostgreSQL and build BM25 text
  from metadata fields. This is the cleanest approach since metadata contains
  all the relevant field values per chunk type.

  B. Load from parent_chunk_text — BM25 over parent chunks directly. But this
  defeats the purpose of child-level retrieval.

  Recommended: Option A. At pipeline startup, load all child chunks' chunk_id,
  parent_record_id, chunk_type, metadata from PostgreSQL (no embeddings needed —
   just the text columns). Build BM25 corpus from metadata JSONB values. Cache
  the BM25 index in memory. This keeps retrieval at the child chunk level for
  both dense and sparse.

  The format for BM25 tokenization:
  # From metadata JSONB: {"company": "...", "category": "...", ...}
  text = " ".join(f"{k} {v}" for k, v in metadata.items() if v and v !=
  "Unknown")
  tokens = text.lower().split()
